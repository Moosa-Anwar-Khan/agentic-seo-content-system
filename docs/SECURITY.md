# Current security boundaries - version 1.2.1

## Identity and approvals

Frontend registration creates pending ordinary members; only administrator activation permits access to runs or credits. When no administrator exists, frontend setup requires a local terminal code that expires after 15 minutes; trusted terminal bootstrap/recovery remains available through `scripts/bootstrap_admin.py`. Authenticator enrollment is required, and temporary-password accounts must change their password. Administrators create trusted reviewer or tax-adviser accounts after password/TOTP confirmation. Professional qualifications must be verified by the administrator, not by the software. Alex/Sam identities are reserved for trusted creation. See [accounts and private history](ACCOUNTS_AND_PRIVATE_HISTORY.md).

Passwords use Argon2id; TOTP secrets use `AUTH_ENCRYPTION_KEY`; recovery codes and 12-hour session tokens are hashed. Session cookies are HttpOnly and SameSite=Strict; HTTPS sets Secure. A session-bound CSRF header is required for business mutations. Logout, reset and disable revoke sessions. Login is throttled. Browser-supplied reviewer names cannot replace authenticated identity.

Professional attestation requires an enabled tax-adviser account and binds identity, time and revision to a fingerprint of the editorial draft, evidence and graphic. Final editorial approval requires Alex/Sam, that current attestation and all release confirmations. Missing/stale graphics, evidence or checks block approval. Social decisions are independent; article-link changes reset the affected approval.

## Data, tools and rendering

Use public/approved business content and aggregated SEO measurements. Client files, tax IDs, private tax assessments and individual case details are outside scope. Text filters reduce risks but cannot guarantee detection of all personal data or prompt injection. Retrieved text and feedback remain untrusted data under fixed instructions. Models have no arbitrary execution, browser, filesystem or publishing tools.

WordPress only exposes controlled public GET reads. `WORDPRESS_READ_ONLY=True` and `ALLOW_WORDPRESS_PUBLISHING=False` cannot enable writes. Broader website discovery is also read-only. Publication records are manual assertions; no posting connector or URL verification is implied.

Official retrieval uses an approved-host allowlist, public-address/DNS and redirect checks, robots policy and bounded text. Tavily discovers candidates only; Firecrawl is an optional eligible extraction fallback with TLS verification and same-host provenance. Neither service establishes tax applicability.

Combined models return validated structured JSON containing constrained Markdown. Code controls HTML/schema generation, strips raw tags/active links, escapes attributes and uses a restricted preview CSP. Export paths are generated by the application; CSV formula prefixes are neutralized. Browser previews are sandboxed.

## Credentials, budgets and recovery

Bootstrap creates a private `.env`; secrets remain server-side and are excluded from exports. Back up the encryption key: changing it makes existing encrypted responses and MFA secrets unreadable. No real credential file belongs in a distributed ZIP.

Atomic per-run token and currency reservations precede tracked paid work. Shared UTC-month limits cover the configured database. Combined text, SEO, Tavily, Firecrawl and optionally enabled paid image calls use the currency ledger. Unknown/uncertain charges retain reservations; vendor invoices and spending outside this application cannot be guaranteed or counted automatically. Use provider-side caps as well. Defaults are documented in README and `.env.example`, not inherited installation logs.

Durable jobs/checkpoints retain completed work and encrypted final replies. Unknown paid outcomes pause for explicit inspection; no hidden paid resubmission on restart. Business state and LangGraph checkpoints are distinct persistence layers; no cross-system exactly-once/ACID guarantee is claimed.

## Operation

SQLite with one backend process and local artifact storage is the supported MVP. PostgreSQL is optional and needs a dedicated validation; migrating both persistence layers and files is deliberate work. Bind locally by default. Shared hosting needs HTTPS, access controls, backups, retention, provider privacy agreements and monitoring. Synchronous compatibility endpoints do not provide all queued-job recovery guarantees. No deployment, paid call or publication is authorized by historical documents.
